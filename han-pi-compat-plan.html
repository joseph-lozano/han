Han Pi compatibility plan

This plan makes Han usable in Pi while keeping the Claude Code plugin files as the source of truth. The work is a small adapter layer, not a permanent rewrite of Han.

Working directory: Pi-compat Target: your Han fork Mode: thin compatibility layer Status: ready to build

Bottom line

The good news is that the missing Pi pieces are now in place. You installed pi-subagents and @juicesharp/rpiv-ask-user-question, which cover the two biggest Claude Code assumptions in Han: specialist agents and structured user questions.

The next step is to teach Han how to present itself to Pi. We can do that with a Pi package manifest, generated Pi-subagent agent files, and a small extension that explains the translation rules to the parent Pi session.

Recommendation: use your fork and build a compatibility layer on top of Han. Keep the existing Han skills and agents canonical, then generate or adapt only the Pi-specific pieces.

Compatibility decisions

Question Decision Reason
Do we rewrite Han for Pi? No. Add a thin Pi layer. Han can stay Claude Code-first while your fork becomes usable from Pi. This reduces drift from upstream.
Where do converted agents live? Generate them into pi/agents, then copy them into the active Pi-subagents user discovery directory through an explicit command. Pi packages can load skills and extensions, but pi-subagents has its own agent discovery locations. The command should target $PI_CODING_AGENT_DIR/agents/han when that environment variable is set, such as inside Orca, and fall back to ~/.pi/agent/agents/han. The destination keeps Han agents grouped; the package source does not need a redundant han subfolder.
Do we preserve model names? Map Han's model tiers onto your Pi models. This fork is for your setup, so keep Han's intent and translate it with one concrete map: haiku → openai-codex/gpt-5.4-mini, sonnet → openai-codex/gpt-5.5:low, and opus → openai-codex/gpt-5.5:xhigh. Pi names the extra-high thinking suffix xhigh.
How do we handle Claude tool names? Convert agent frontmatter and add parent-session compatibility guidance. Agents need lowercase Pi tool names. Skills need guidance so the parent maps Agent to subagent.
How do we handle ${CLAUDE_SKILL_DIR}? Patch Pi-facing skill copies or add explicit compatibility guidance that resolves scripts relative to the active skill directory. Pi does not define that environment variable. Running it literally would fail.

Implementation phases

Package Han for Pi

Add a root package.json with a pi manifest. The manifest should load Han skills from han.core/skills, han.github/skills, han.reporting/skills, han.feedback/skills, and the compatibility extension from pi/extensions.

{
  "name": "han-pi-compat",
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./pi/extensions/han-pi-compat.ts"],
    "skills": [
      "./pi/skills/han.core/skills",
      "./pi/skills/han.github/skills",
      "./pi/skills/han.reporting/skills",
      "./pi/skills/han.feedback/skills"
    ]
  }
}

Generate Pi-subagent agent files

Create scripts/generate-pi-agents.mjs. It reads han.core/agents/*.md, converts tool names, maps Han's model tiers to your configured Pi model IDs, and writes the results to pi/agents/*.md.

Add the compatibility extension

Create pi/extensions/han-pi-compat.ts. It should add parent-session guidance before each agent turn and register a command that installs the generated Han agents into Pi-subagents' discovery directory.

// command behavior
/han-pi-install-agents

// copies
pi/agents/*.md

// to
$PI_CODING_AGENT_DIR/agents/han/*.md
// or, outside an overlay:
~/.pi/agent/agents/han/*.md

The extension should not silently write global agent files on startup. Make the user run the command once so the filesystem change is explicit.

Patch the Pi-facing skill instructions only where needed

Use generated Pi-facing skill copies under pi/skills so canonical Han skills stay Claude Code-first. Normalize only metadata that blocks loading, such as YAML-sensitive argument hints. Preserve original descriptions even when Pi warns that they exceed 1024 characters, because that warning does not prevent loading. Preserve sibling references/ and scripts/ directories. The generator also patches Pi-facing body text for concrete model IDs and Han agent runtime names. Keep broader runtime behavior translation in the compatibility extension unless smoke tests prove a skill body needs another concrete generated patch.

Keep these patches generated or documented so upstream Han changes remain easy to merge.

Add a doctor command

Add /han-pi-doctor to check the local setup. This should report whether the required Pi packages are installed, whether Han agents are visible to pi-subagents, whether pi-web-access is installed for research flows, and whether the current project has loaded Han skills.

Run smoke tests

Use a small set of workflows that exercise each compatibility seam before treating the fork as usable.

  • /skill:issue-triage for a skill that does not need subagents.
  • /skill:test-planning for parallel specialist agent dispatch.
  • /skill:stakeholder-summary for writing a report file.
  • /skill:html-summary for script path handling.
  • /skill:research after installing npm:pi-web-access.

Install flow after the layer exists

The intended user flow should be short. You install the Pi dependencies, install Han from your fork, then run one setup command for the agents.

pi install npm:pi-subagents
pi install npm:@juicesharp/rpiv-ask-user-question
pi install npm:pi-web-access
pi install git:github.com/YOU/han@pi-compat

# Restart Pi or run /reload, then:
/han-pi-install-agents
/han-pi-doctor

Risks and controls

Risk

The parent Pi model follows Claude instructions literally

Control: inject clear compatibility guidance and smoke-test the highest-value skills. Patch repeated failures in generated Pi-facing skill copies.

Risk

Model aliases drift from your Pi setup

Control: keep one compatibility model map for haiku, sonnet, and opus. The doctor command should verify those concrete Pi model IDs still exist before generated agents use them.

Risk

Script paths fail because CLAUDE_SKILL_DIR is missing

Control: patch script references to use the skill directory wording, or provide generated Pi skill copies for script-heavy skills.

Risk

Upstream Han changes drift from the fork

Control: keep canonical files unchanged where possible and make Pi artifacts generated. Regenerate after every upstream merge.

Definition of done

  • pi install git:github.com/YOU/han@pi-compat loads Han skills and the compatibility extension.
  • /han-pi-install-agents installs converted Han agents into the active Pi-subagents user discovery directory, using $PI_CODING_AGENT_DIR/agents/han when set and ~/.pi/agent/agents/han otherwise.
  • /han-pi-doctor reports all required Pi dependencies and visible Han agents.
  • A parent Pi session can run at least one subagent-heavy Han skill through pi-subagents.
  • A self-contained skill such as stakeholder-summary works without Claude Code.
  • The compatibility layer is documented in pi/README.md with install and troubleshooting steps.
